## 结构选择与原结构的区别

| 方案 | 结构和代价 | 结论 |
| --- | --- | --- |
| 四张关联表，沿用配置基础框架 | 分离目录、棋盘、约束和主题；新读取器连接引用并编译约束 | 推荐，支持独立校验和换皮 |
| 每关一个自主 JSON 载荷 | 字段可变化，但仍是一行包一整关，约束无法独立检索 | 本版不采用 |
| 自主二进制资源 | 增加构建和诊断成本，编码本身不产生业务模型差异 | 当前无必要 |

| 现有/原版定义 | 自主定义 | 实质变化 |
| --- | --- | --- |
| ID 同时表示身份和顺序 | 目录 Id 与 OrderIndex | 稳定身份与展示关号分离 |
| 单表 LevelJsonData 内嵌题面 | 目录外键关联棋盘和约束集合 | 多实体关系模型，无整关 JSON 单元格 |
| size + holes + givens 坐标对象 | Columns + Rows + Cells | 单一格状态平面，不再分散保存空洞与固定格 |
| regions / edges / edgeClues / cornerClues 多组数组 | 每条约束一行，由 Op 区分类型 | 统一约束记录及参数验证 |
| s / symbol 数值与皮肤名称混用 | Slot=A/B，外接主题表 | 题库不定义图案身份 |
| 解析旧 JSON 后直接建关卡 | 连接表、解码棋盘、编译约束、验证整库 | 自主解析入口，不回转旧协议 |

现有框架必须的通用 Id、Excel 容器和 gamedata.json 打包形式可以保留。它们不是原版特有的关卡业务模型，无需为改名重写整个框架。

## 中性符号与主题分离

协议固定两种逻辑符号：A、B。源 1 → A、源 2 → B；内部兼容映射为 A → 1、B → 2，永久稳定。换图标不能交换槽位，空格和空洞不属于图案槽位。

关卡、约束、答案、提示及教学步骤均引用 A/B，不出现 angel/devil、sun/moon 等美术语义。现有内部整数可以保留，新类型和接口使用 SymbolSlot，不根据资源名称推断规则。

symbolSkin 表把槽位映射到主题图标、本地化名称和落子音效。题库不引用具体主题，应用通过 ActiveSymbolStyle 选择主题；本次只需配置默认主题，不要求开发玩家换肤页面。

统一主题解析入口覆盖棋盘固定格与动态格、选择器、边缘/交点数字标记、规则卡、独立演示、强弱引导、提示预览、胜利反馈和图案音效。历史资源文件名可暂时保留，但只能位于主题映射或渲染适配层，不能进入关卡协议和规则分支。

规则文案采用“首个指定图案的位置”等中性表达；需要具体名称时使用现有语言系统的 `{0}`、`{1}` 参数，由主题提供名称。教学图和动画使用相同图标入口。首页等完整装饰图片继续沿用现有美术，换主题时应另行提供对应装饰资源。

## 四张配置表

现有生成器支持 string/int/float，以下沿用这些类型；布尔标记使用受约束的 0/1。每表保留框架主键 Id，不增加整关 JSON 载荷列。

### 1. 关卡目录 Excle/puzzleRoute.xlsm

每关一行，首批 400 行。所有内容表同批发布。

| 字段 | 类型 | 定义 |
| --- | --- | --- |
| Id | string | 稳定身份 hd-main-0001～hd-main-0400，重复转换不得随机更换 |
| OrderIndex | int | 显示顺序 1～400，不从 Id 字符串推导 |
| CatalogKey | string | 题库身份，首批 main |
| FormatRevision | int | 自主协议版本，首版 1 |
| ContentTag | string | 内容版本，首批 rf400-20261010 |
| BoardRef | string | 棋盘表 Id，如 board-main-0001 |
| ClauseSetRef | string | 约束表 SetRef，如 clauses-main-0001 |
| Grade | int | 原难度标签，当前 1～5 |
| Featured | int | 困难标记，仅 0/1，当前共 69 个 1 |
| RuleDeck | string | 有序自主规则枚举，英文逗号分隔，不从实际约束反推 |
| CutoutMode | string | ornament/open，对应原 cloud/frame，保持当前表现 |
| PuzzleHash | string | 解析后规范化棋盘和约束的 SHA-256 |

首版每关各有独立棋盘及约束集合，不跨关去重或共享。RuleDeck 使用六种 Op 加 cutout；cutout 仅为教学/展示标识。本批实际含空洞 214 关，源规则列表显式含 holes 仅 97 关，保留这种区别。

### 2. 棋盘布局 Excle/puzzleBoard.xlsm

| 字段 | 类型 | 定义 |
| --- | --- | --- |
| Id | string | 被 BoardRef 引用的棋盘身份 |
| Columns | int | 列数，首版只接受 4、6、8 |
| Rows | int | 行数，首版要求等于 Columns |
| Cells | string | 行优先 ASCII 状态串，长度严格等于 Columns × Rows |

Cells 每个字符对应一格：`.` 可填空格、`#` 空洞、`A` 固定 A、`B` 固定 B。不接受空格、换行、小写或其他字符，避免同一格同时出现在空洞和固定格数组。

索引从左上角 0 开始：`cell = row × Columns + column`。最新版第 1 关真实布局：

```text
B..A
.ABB
..AB
.ABA
```

对应完整棋盘行：

| Id | Columns | Rows | Cells |
| --- | --- | --- | --- |
| board-main-0001 | 4 | 4 | B..A.ABB..AB.ABA |

正式 Cells 只有一行、16 个字符。解析器生成内部 -1/0/1/2 棋盘；玩家落子属于存档，不写回 Cells。

### 3. 约束明细 Excle/puzzleClause.xlsm

每条约束一行，同关使用相同 SetRef。

| 字段 | 类型 | 定义 |
| --- | --- | --- |
| Id | string | 唯一约束身份，如 clause-main-0001-0001 |
| SetRef | string | 对应目录 ClauseSetRef |
| Order | int | 集合内从 1 开始连续的编译顺序 |
| Op | string | 下表六种自主约束操作 |
| Axis | string | 使用时固定 both，表示行和列 |
| CellRefs | string | 有序扁平索引，英文逗号分隔，如 0,4；单索引如 4 |
| ZoneLabel | int | 使用时保留原区域编号 |
| Relation | string | 使用时为 same/opposite |
| Edge | string | 使用时为 west/north |
| Lane | int | 使用时为从 0 开始的行号或列号 |
| Slot | string | 使用时为 A/B |
| Amount | int | 上限、位置或数量，由 Op 决定语义 |

下表列出各 Op 的全部有效参数，其余 string 列必须为空串、int 列必须为 -1，不允许携带无意义参数。不能用 0 表示空参数：0 是合法索引、区域编号和交点数量。CellRefs 文法为非负十进制整数及逗号，无空白、空项或前导零；不使用 JSON 或脚本表达式。

| Op | 必需参数 | 精确含义 |
| --- | --- | --- |
| trackBalance | Axis=both | 每行每列有效格中 A/B 等量；排除空洞，有效格数为偶数 |
| runCeiling | Axis=both, Amount=2 | 物理相邻格不能连续三个同类；空洞打断连续，不压缩棋盘后判连三 |
| districtBalance | ZoneLabel, CellRefs | 区域内有效格 A/B 等量；编号保留，不重排颜色 |
| pairRelation | CellRefs 恰好两项，Relation | 两个物理相邻有效格相同或相反，端点顺序保持源顺序 |
| entryPosition | Edge, Lane, Slot, Amount | 从左/上方看，跳过空洞，首个指定槽位位于第 Amount 个有效格，Amount 从 1 开始 |
| junctionCount | CellRefs 恰好一项，Slot, Amount | 该索引为物理 2×2 左上角，其中有效格的指定槽位数量等于 Amount |

首版每关恰好一条 trackBalance 和一条 runCeiling。空洞打断连续是协议语义，不设可变开关。entryPosition 不接受东/南侧；junctionCount 锚点不在最后一行/列，数量范围为 0～该 2×2 的有效格数。

区域成员包含源区域表该编号的所有格子，即使遇到带编号空洞也不丢失，求解时再排除空洞。无归属恢复为 -1，区域不得重叠。本批编号为 0～7；协议允许其他非负编号，但显示层必须能解析配色，否则发布校验失败。二维或扁平区域统一按棋盘首次出现编号的顺序生成记录，成员按行优先排列。

记录顺序固定为基础两条、区域、相邻关系、边缘数字、交点数字；后三类保持各自源数组顺序，不去重、不合并。本批有 42 条相邻关系端点不是升序，必须保留。

第 1 关仅有 Order=1 的 trackBalance 和 Order=2 的 runCeiling。第 330 关除基础两行外，另外三行真实线索如下，未展示参数使用上述空值：

| Order | Op | Edge | Lane | Slot | Amount |
| --- | --- | --- | --- | --- | --- |
| 3 | entryPosition | west | 2 | A | 3 |
| 4 | entryPosition | west | 0 | B | 2 |
| 5 | entryPosition | north | 3 | A | 2 |

B 没有“恶魔”的协议含义。数字标记渲染当前主题的 B 图标，始终表示“第 0 行首个 B 位于第 2 个有效格”。编译到现有 LumaClue.Value 时须减 1，避免 DisplayValue 再加 1 后错位。

## 自主解析形式与代码边界

加载链路：

`main.json / themes.json → 四表导出 → 现有编译器 → gamedata.json → 四个 ConfigMgr → 引用连接、棋盘解码、约束编译 → LumaLevel → LumaSolver / LumaSession`

新增 PuzzleRouteConfigMgr、PuzzleBoardConfigMgr、PuzzleClauseConfigMgr、SymbolSkinConfigMgr，更新 `UnityWork/Assets/HotUpdate/Xs/ConfigInsResgister.cs`。所有表完成加载后才建立题库，不依赖回调顺序碰巧正确。

- PuzzleCatalogReader：建立身份、顺序、外键索引，验证整库版本、引用和完整性。
- BoardLayoutDecoder：只识别 Cells 四种状态，生成内部初始棋盘。
- 约束编译：由 PuzzleCatalogReader 校验参数，再由 LumaLevel 的内部构造函数直接构建 Regions、Edges、Clues、LumaConstraint；没有单独的 PuzzleConstraintCompiler 类，也不重建旧 JSON。
- SymbolThemeResolver：解析槽位对应的图标、名称、音效，不参与求解或题面指纹。
- LumaLevel：保留现有游戏接口，以类型化定义构建，补稳定身份和指纹；旧 JSON 路径退出正式加载。
- LumaSolver/LumaSession：保留规则算法，调整入口、教学引用和存档迁移。

基础两条 Op 合并编译，按现有 LumaLevel 行/列交替顺序交织生成平衡和连三约束，不能先生成全部平衡再生成全部连三。然后生成区域、关系、边缘和交点约束，保持提示求值顺序。

内部 row/col/nothree/region/edge/first/corner 可保留为实现细节，由一份映射连接自主 Op、规则卡和提示，明确 first → entryPosition。主线仍按 OrderIndex 构建 1～400 列表，不能按身份字符串排序。

本轮仅调整 Unity。网页端及其 Python 工具已恢复原状，不纳入本次验收。Unity 正式运行时不保留旧格式双读或静默回退，历史格式仅供来源审计。

## 校验、指纹与等价性

内容与主题的 JSON Schema 位于 schemas，运行时跨表语义校验由 PuzzleCatalogReader 完成。既有 Python 编译器保持原样，仅负责通用表编译；发布前必须执行实际编译配置的 C# 回归，以验证整库。至少拒绝：

- 未知版本、Op、槽位、方向、额外业务字段；必需参数遗漏或不适用参数误填。
- 身份或顺序重复、关号不连续、版本混用、悬空引用、未引用棋盘/约束集合、首版跨关共享引用。
- Cells 长度/字符非法、非法尺寸、索引越界、关系端点不相邻或位于空洞。
- 区域重叠、重复成员、有效格数为奇数、负数区域编号；合法编号按现有调色盘循环映射。
- 线索超范围、基础约束重复/缺失、约束顺序不连续、主题映射不完整。
- PuzzleHash 不匹配，展示列表、难度和困难标记与源不等价。

验收分四层：

1. **源语义等价。** 两种格式分别还原为审计描述，比较全部题面、区域编号、端点及线索顺序、展示列表、难度、困难标记和关号，不能只比较解。
2. **内部模型等价。** 比较实际 C# 两条路径生成的 Initial、Regions、Edges、Clues、约束及求值顺序；规则名显式映射后对照。
3. **求解与会话等价。** 新解析器的 400 关全部唯一解且与源一致，重跑提示、解锁、判错、失败、复活、通关、读档及迁移；旧报告不能替代。
4. **产物一致。** XLSM、StreamingAssets/Remote 正式 Config、自主 JSON 和 Unity 夹具属于同版，旧表退出正式产物。原 Python 编译器不写 Excle/gamedata.json，不能以该历史文件判断正式版本。

PuzzleHash 覆盖尺寸、格状态和有序约束，不覆盖记录 Id、主题、文案、显示难度或发布版本。规范化文本首行为 ColumnsxRows，第二行为 Cells，后续按 Order 每条约束一行，依次拼接 op|axis|cellRefs|zoneLabel|relation|edge|lane|slot|amount（包含未使用字段的空串或 -1），行间 LF、末尾无换行，再取 UTF-8 SHA-256。不能散列工作簿字节。发布目录的整个 gamedata.json 另用文件指纹核对。

重点回归：99 关扁平区域及 3 关二维区域、第 330 关混合槽位、含空洞的边缘位置、交点数量 0/4、第 389 关，以及切换两套测试图标前后答案、提示目标、PuzzleHash 不变。测试皮肤不要求成为产品功能。
